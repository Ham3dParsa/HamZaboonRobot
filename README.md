# هم‌زبان — نسخه‌ی MVP ربات تلگرام

## اجرا

```bash
python -m venv venv
source venv/bin/activate   # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env       # و مقادیرش رو پر کن
python bot.py
```

## ساختار
- `config.py` — خواندن تنظیمات از `.env`
- `db.py` — دیتابیس sqlite (کاربران، واژه‌های ذخیره‌شده، تنظیمات قابل‌تغییر توسط ادمین)
- `prompts.py` — پرامپت‌های سیستمی (تنها جایی که "منطق محتوا" است)
- `ai.py` — کلاینت سازگار با OpenAI API که تنظیماتش را زنده از دیتابیس می‌خواند
- `keyboards.py` — کیبوردهای reply و inline
- `bot.py` — هندلرها و اجرای اصلی

## نکات ادغام با AI API (به‌خصوص gapgpt)

1. **کلید API که در چت پیست کردی را همین الان از پنل gapgpt ریوک/عوض کن.**
   هر متنی که داخل یک چت (حتی با من) رد و بدل شود، دیگر «محرمانه» حساب نمی‌شود؛
   کلیدهای API را هیچ‌وقت داخل کد یا پیام قرار نده، همیشه در `.env` (که در `.gitignore` باشد).

2. gapgpt یک اندپوینت سازگار با OpenAI SDK می‌دهد (`base_url` عوض می‌شود، بقیه‌ی کد OpenAI عیناً کار می‌کند).
   به همین دلیل در این پروژه از پکیج رسمی `openai` استفاده شده، نه یک کلاینت دست‌ساز.

3. **نام مدل را همیشه بر اساس مستندات لحظه‌ای gapgpt تنظیم کن، نه حدسی.** اسم‌هایی مثل
   `gpt-5.6-luna` نامِ سرویسِ پروکسی است، نه لزوماً نام مدل واقعی OpenAI؛ این‌جور اسم‌ها زود عوض می‌شوند —
   برای همین در این پروژه نام مدل هاردکد نشده و از پنل مدیریت ربات قابل تغییر است.

4. **مدیریت خطا اجباری است.** سرویس‌های پروکسی مثل gapgpt گاهی timeout می‌دهند یا خروجی غیر-JSON
   برمی‌گردانند (مثلاً با توضیح اضافه دور JSON). به همین خاطر `ai.py` هم regex برای تمیزکاری دارد
   و هم try/except در بالادست، تا کاربر پیام خطای فنی خام نبیند.

5. **هزینه را جدا از تعداد کاربر رصد کن.** چون هسته‌ی محصول مدل‌محور است (نه هاردکد)، هر تعامل کاربر
   دست‌کم یک فراخوانی API دارد. برای MVP این مشکلی نیست، ولی وقتی کاربر واقعی اضافه شد، حتماً
   لاگ مصرف توکن/هزینه به‌ازای هر کاربر و هر پلن نگه دار — همان‌طور که در سند قیمت‌گذاری هم اشاره شده بود.

6. **تفکیک مدل بر اساس پلن** (که در سند اولیه خواستی) در همین معماری راحت اضافه می‌شود: کافی است
   در `db.py` یک ستون `ai_model` هم برای *پلن* (نه فقط global) نگه داری، یا در `ai.ask_json` پارامتر
   پلن کاربر را بگیری و بر اساس آن `_model()` را عوض کنی. در این نسخه‌ی MVP یک مدل global برای
   سادگی استفاده شده؛ افزودن تفکیک، یک تغییر کوچک است نه بازنویسی.

## محدودیت‌های عمدی این نسخه (مطابق سند MVP)
- بدون تصویر AI، بدون تست سطح واقعی، بدون گروه/رتبه‌بندی — طبق فاز صفر سند.
- پرداخت/ارتقای پلن به‌صورت دستی توسط ادمین است (`db.set_plan`)؛ اتصال به درگاه در فاز بعد اضافه می‌شود.
